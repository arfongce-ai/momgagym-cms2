# 적용 방법 (교차검증 완료본) — 보행/러닝 라이브+업로드+슬로모+종합리포트

23개 테스트 통과. 전 컴포넌트 컴파일 + 데이터계약 일관성 + 대시보드 렌더 검증 완료.

## 파일

```
src/ai-measure/core/
  ├ gaitBiomechanics.js     ← 교체 (고급지표 BiomechAccumulator 포함)
  └ videoAnalyzer.js        ← 신규 (업로드 엔진 + 슬로모 시간축 보정)
src/ai-measure/menus/
  ├ GaitAnalysisHub.jsx     ← 신규 (라이브/업로드 분기 + 리포트 진입)
  ├ GaitUploadAnalysis.jsx  ← 신규 (업로드 분석 + 촬영모드)
  └ GaitReportDashboard.jsx ← 신규 (A4 1장 종합리포트)
_apply_notes/
  ├ GaitRunningAnalysis.patched.jsx       ← 패치 적용된 라이브 컴포넌트(전체본)
  └ GaitRunningAnalysis.handleSave.patch.js ← 수동 반영용 4곳 가이드
```

## 반영 순서

### 1. core/menus 5개 파일 복사 (덮어쓰기/신규)

### 2. GaitRunningAnalysis.jsx — 둘 중 택1
   - (A) 기존 파일을 직접 안 고쳤다면: `_apply_notes/GaitRunningAnalysis.patched.jsx`
     를 `src/ai-measure/menus/GaitRunningAnalysis.jsx` 로 덮어쓰기 (가장 간단).
   - (B) 그 사이 직접 수정한 게 있다면: `handleSave.patch.js` 의 4곳만 수동 반영
     (import / ref / 녹화루프 push / onstop metrics). UI/JSX 무변경.

### 3. registry.js — 진입점 교체
```js
{ id: 'gait', no: 10, title: '보행 & 러닝',
  desc: '실시간·영상업로드 · 각도·케이던스·주기', icon: '🏃',
  status: 'ready',
  component: lazy(() => import('./menus/GaitAnalysisHub.jsx')) },
```

### 4. ★ recharts 의존성 확인 (대시보드 차트용)
```
npm ls recharts || npm i recharts
```
없으면 빌드가 깨집니다. package.json 에 추가 후 커밋하세요.

### 5. (선택) demoData.js addGaitReport 가 저장본을 반환하게
대시보드 코멘트가 정확한 문서를 갱신하려면 저장 함수가 id 포함 객체를
반환해야 합니다. 이미 `return r;` 하고 있으면 그대로 동작합니다.
```js
addGaitReport: async (report) => {
  const r = { ...report, id: uid('gait'), createdAt: new Date().toISOString() };
  await fbSet('gait_reports', r.id, r);
  return r;   // ← 이 반환이 있어야 코멘트 타겟팅이 정확
},
```

## 교차검증에서 발견·수정한 문제들
1. 라이브 모드에 종합리포트 진입 경로 부재 → '📊 리포트' 버튼 추가(자동이동 강제 안 함, 영상 미리보기 흐름 보존)
2. 모드 토글이 라이브 헤더와 겹침 → 상단 중앙 오프셋 배치, 측정화면에서만 노출
3. 업로드/Hub 이중 저장 위험 → 저장 책임을 Hub 단일화
4. report.id 부재로 코멘트 타겟 불가 → 저장본(id) 캡처, 없으면 코멘트 비활성화
5. 빈/구버전 데이터 대시보드 렌더 → normalizeMetrics 폴백으로 무crash 확인
6. A4 비율 모바일 가독성 → minHeight 바닥값 + 스크롤 허용
