# AI 협업 단일 접수판

Codex, Claude, Gemini는 서로의 대화창을 직접 읽거나 자동으로 메시지를 주고받지 못한다.
이 저장소에서는 GitHub와 아래 문서를 하나의 기록으로 사용한다. 비밀값, 토큰, 회원 이름·연락처·원본 영상은 절대 기록하지 않는다.

## 사용자: 질문은 한 곳에만 남긴다

모바일에서는 GitHub Issue를 우선 사용한다. Issue 제목은 `작업: 짧은 목표`로 쓰고, 본문에는 아래만 적는다.

```text
목표:
완료 기준:
수정 가능 범위:
금지 사항:
확인할 점:
```

GitHub Issue를 쓰기 어려우면 Codex 또는 Claude 대화 중 한 곳에만 질문을 남기고 다음 문장을 덧붙인다.

```text
이 요청을 docs/HANDOFF.md에 기록하고, 다음 AI가 이어서 검토할 수 있게 해줘.
```

## AI: 같은 순서로 작업한다

1. `AGENTS.md`, `docs/HANDOFF.md`, 해당 GitHub Issue를 읽는다.
2. 다른 도구의 작업 잠금과 미커밋 변경이 있으면 같은 파일을 수정하지 않는다.
3. 작업 범위·파일·테스트 결과·남은 위험을 `docs/HANDOFF.md` 작업 로그에 남긴다.
4. 코드 변경은 작은 커밋으로 만들고, 사용자 요청 방식으로 GitHub에 올린다.
5. 다음 AI는 `docs/REVIEW_LOOP.md` 절차에 따라 교차 검토한다.

## 역할 분리

| 역할 | 담당 |
|---|---|
| 요청·사업 판단·공개 승인 | 사용자 |
| 구현 또는 설계 | 먼저 작업한 AI(Codex/Claude/Gemini) |
| 교차 검토 | 다른 AI 1개 |
| 최종 배포 승인 | 사용자 |

Gemini는 저장소에 직접 접근 가능한 환경일 때만 구현·검토 담당으로 참여한다. 접근 권한이 없다면 Issue와 HANDOFF 내용을 기준으로 설계 검토만 한다.

## 모바일용 최소 명령

- Claude: `momgagym-cms2의 docs/HANDOFF.md와 이 Issue를 읽고, Codex 결과를 검토한 뒤 다음 단계만 진행해줘.`
- Codex: `docs/HANDOFF.md와 이 Issue를 확인하고, Claude 결과를 검토해서 다음 단계 진행해줘.`
- Gemini: `아래 GitHub Issue와 docs/HANDOFF.md 내용을 기준으로 설계·보안 관점에서 빠진 점만 검토해줘.`

## 콘텐츠·영상 작업의 추가 원칙

- 회원 원본 영상은 내부 저장소에 보관한다.
- 공개 자동화에는 공개 동의와 사용 범위가 확인된 복사본만 넣는다.
- 공개 콘텐츠와 회원·결제·측정 데이터는 별도 컬렉션·별도 앱 번들·별도 API 경로로 분리한다.
- 자동 제작 결과는 게시 전 사람이 검수·승인한다.
