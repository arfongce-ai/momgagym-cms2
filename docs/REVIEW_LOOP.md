# REVIEW_LOOP — Claude 작업을 Codex가 검토·보완하는 절차

`AGENTS.md` 25줄 "상호 검토"의 세부 절차입니다.
공개 저장소이므로 비밀값·개인정보·직원/회원 이름·실제 매출 금액을 쓰지 않습니다.

## 역할

| 역할 | 누가 | 하는 일 |
|---|---|---|
| 작성자 | Claude (claude.ai 프로젝트 대화, Claude Code, Cowork) | 기능 구현, 끝나면 `docs/REVIEW_QUEUE.md`에 항목 추가 |
| 검토자 | Codex | 검사 → 기록 → (사용자 승인 후) 보완 |
| 결정자 | 사용자 | 수정 진행 여부, 업로드(`1_GITHUB_UPLOAD.bat`), 배포 |

Codex가 새 기능을 만든 경우에는 역할만 바꿔 같은 절차를 씁니다(Codex가 대기열에 항목 추가 → Claude가 검토).

## 1회 검토 = 대기열 항목 1개

1. **준비**
   - `git branch --show-current` → `main`이 아니면 멈추고 보고. (`agent/codex-claude-sync`는 main과 크게 어긋난 옛 브랜치 — 사용 금지)
   - `git status --short` → 미커밋 변경이 있으면 건드리지 말고 보고.
   - `docs/HANDOFF.md` 작업 잠금 표에 `Codex | 검토 R? (대상 파일) | 시작 일시` 기록.
2. **기준선 확인**
   - `npm test` → 통과 수를 `.github/test-baseline.json`의 `minPassing`과 비교.
   - HANDOFF "기존 11개 실패" 절의 알려진 실패는 새 실패로 세지 않음.
3. **검사** — 대기열 항목의 "대상"과 "확인할 것" 범위만
   - 항목의 커밋을 먼저 본다: `git show --stat <해시>` → 필요한 파일만 diff. (Codex `/review`에서 커밋 지정 방식도 가능)
   - 요구사항대로 동작하는가 / 기존 기능을 깨지 않았는가
   - 경계값: 0원, 빈 배열, null·undefined, 같은 날짜 2건, 나누어떨어지지 않는 금액
   - 테스트가 동작을 실제로 잠그는가 (소스 문자열만 찾는 테스트는 "약함"으로 표시)
   - 재현이 필요하면 `src/__tests__/review_R?_*.test.js`로 작성·실행 — 보완 단계 전까지 커밋하지 않음
   - UI·import 변경이 있으면 `npm run build`
4. **기록 (고치기 전에 먼저)** — 아래 형식으로 HANDOFF 작업 로그 맨 위에 추가
5. **보완 (사용자가 "진행"이라고 답한 뒤에만)**
   - 발견 1건 = 커밋 1개, 기존 코드에 덧붙이는 최소 수정. 큰 파일 전체 덮어쓰기 금지
   - 수정마다 회귀 테스트 추가 (가능하면 실제 실행형)
   - `npm test` 재실행 → 통과 수가 줄지 않았는지. 기존 실패를 고쳤으면 `minPassing` 상향
6. **마무리**
   - `docs/REVIEW_QUEUE.md` 해당 항목 상태 변경
   - 작업 잠금에서 내 줄 삭제, 작업 로그 완료
   - 푸시하지 않음 — 사용자가 `1_GITHUB_UPLOAD.bat` 실행

## 심각도

- 🔴 치명: 금액·회차·측정값이 틀리게 저장/표시, 데이터 손실, 권한 우회
- 🟠 중요: 특정 조건에서 오동작, 실패가 조용히 묻힘, 화면 숫자끼리 불일치
- 🟡 경미: 문구·표시, 약한 테스트, 죽은 코드·중복

## 하지 않는 것

- 대기열 항목 범위 밖 리팩터링
- 확인 안 된 Firestore 필드명 추측 — 모르면 "사용자 확인 필요"로 기록
- 정산 규칙·측정 계산식을 근거 없이 변경 — 규칙이 불분명하면 사용자에게 질문
- 커밋 히스토리 재작성, 파일 영구삭제

## HANDOFF 작업 로그 형식 (검토용)

```
### YYYY-MM-DD HH:MM · Codex · 검토 R? 항목명
- 한 일:
- 발견: 🔴/🟠/🟡 파일:줄 — 내용 / 근거
- 테스트: npm test → 통과 N/M (기준선 minPassing)
- 제안 수정:
- 남은 위험:
- 사용자 결정 필요:
- 다음에 할 일:
```

## Claude로 돌아가는 길

사용자가 업로드한 뒤 Claude 프로젝트 대화에서 "코덱스 검토 확인"이라고 하면,
Claude가 GitHub 저장소를 직접 받아 HANDOFF 작업 로그와 REVIEW_QUEUE를 읽고 교차 확인합니다.
